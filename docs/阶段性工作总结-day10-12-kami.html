一、夯实基础 —— 三项高优改进

1.1 真实 CRC-24 生成 completed

改动细节
CrcService.java 重写 从 long（64 位）改为 BigInteger，正确计算 112 位 ADS-B 报文的 CRC-24 余数。生成多项式 0x1FFF409（对应 ADS-B 标准 0xFFFA0480）
generatePositionHex() PI 字段从固定 "000000" 改为 crcService.generate(body)
tick() crcValid 从硬编码 true 改为 crcService.isValid(rawHex)
buildMessage() 去掉 crcValid: boolean 参数，统一自动校验

1.2 默认切 MySQL completed

application.yml添加 spring.profiles.active: mysql，默认使用 MySQL 持久化。密码配置文件保持 gitignored
持久化验证重启后端后飞机和报文数据保持，不再丢失。告警记录跨重启保留

1.3 位置跳变检测完善 completed

原方案仅对比相邻两条报文距离
新方案维护每架飞机最近 5 个位置点的滑动窗口，计算中位数位置，新位置偏离中位数 > 100km 判定为 GPS 欺骗。检测到跳变后清空窗口重新积累

二、生产构建踩坑全记录

从 Vite 开发服务器切换到 Spring Boot 内嵌静态文件部署时，经历了一系列连锁问题：

#问题根因解决方案
1 地图不显示，报 appendChild 错误 SVG divIcon 在生产构建中 DOM 操作失败 改为 L.circleMarker（Leaflet 内置 SVG 渲染，不操作 DOM）
2 地图仍不显示，OSM 瓦片超时 tile.openstreetmap.org 在中国被墙 换为高德地图瓦片 webrd0{s}.is.autonavi.com
3 SPA 路由刷新 404 Spring Boot 不知道 /aircraft 等路径要返回 index.html 添加 SpaFallbackFilter，非 API/非静态资源请求转发到 /index.html
4 旧 JS 文件积压，浏览器加载过期版本 mvn package（非 clean）不会清空 target/classes/static/，多次构建的 hash 文件名堆积 每次部署前 mvn clean + 清空 src/main/resources/static/ + 重新复制 dist
5 首页数据不刷新（攻击后异常数不变） 浏览器缓存了 API 响应（GET 请求被浏览器直接返回缓存） Axios 请求拦截器给所有 GET 请求加 _t=Date.now() 时间戳破缓存
关键教训：Vite 开发模式下一切正常 ≠ 生产构建也正常。三个最隐蔽的差异——① divIcon 的 DOM 创建时序在生产 bundle 中不同；② 浏览器对 GET 请求的缓存策略比开发模式激进得多；③ Maven 不 clean 时旧资源残留导致 jar 中包含多版本 JS 文件。

三、攻击模拟系统 —— 五种攻击全覆盖

攻击类型告警等级飞机状态检测方式
📍 位置欺骗 (GPS Spoofing)红色→ 异常滑动窗口中位数对比，偏离 > 100km
📏 高度篡改橙色→ 异常相邻报文高度差 > 5000ft

🔐 CRC 篡改红色→ 异常真实 CRC-24 校验失败
🔄 重放攻击红色→ 异常60 秒内相同 hex 报文重复

告警管理

新增「清空全部告警」按钮（确认弹窗 + DELETE /api/alerts），防止告警堆积。同时清除安全检测的去重缓存，允许同类告警再次触发。

四、状态持久化修复

原问题DataInitRunner 每次启动调用 seedAircraft()，内部 deleteAll() 删光所有飞机重建。攻击后标记的「异常」状态重启即丢失
修复DataInitRunner 仅在 aircraftRepo.count() == 0 时种子数据；seedAircraft() 移除 deleteAll()。攻击后的异常状态跨重启保持

五、现存问题 & 后续改进方向

5.1 飞机状态管理不便

现状：目前修改飞机状态的唯一途径是通过攻击模拟——触发安全检测 → 自动标记为异常。没有手动设置飞机状态的方式，调试时需要反复点击攻击按钮，且攻击目标是随机的，无法精确控制哪架飞机变异常。

建议方案：
  • 在飞机列表页每行增加一个状态切换开关（正常 ⇄ 异常），直接调 API 修改
  • 或增加 PUT /api/aircraft/{icao}/status 接口，前端加下拉选择
  • 在仿真控制页增加「一键异常」按钮——随机选 N 架的批量操作

5.2 系统功能偏少

现状：系统目前本质上是一个「ADS-B 飞机模拟器 + 安全告警检测器」。仿真控制只能启停和调飞机数量，缺乏对仿真参数的深度控制。安全检测只有 5 条规则。数据可视化只有一张饼图。

建议方向：
模块可增加功能
仿真控制手动设置飞行航线（起降点+航路点）、调整仿真速度（1x/10x/100x）、暂停/单步执行、选择特定空域（北京/上海/广州终端区）
数据可视化实时高度-速度散点图、报文类型分布柱状图、告警时间线、单架飞机的航迹回放
安全检测航路偏离检测、ADS-B 协议字段一致性校验（如高度源与 TC 匹配）、时间戳异常检测
报文解析支持拖拽批量导入 hex 文件、解析结果导出 CSV、报文字段的可视化标注
加密模块按项目计划第三周集成身份基广播加密，在报文上加解密标记

5.3 菜单栏单调

现状：左侧导航只有 6 个图标 + 文字菜单项，纯功能罗列，没有层次感和品牌识别度。

建议方案：
  • 顶部增加系统 Logo 和项目名称（带副标题）
  • 菜单分组：监控（首页、飞行器列表、数据可视化）、分析（报文解析）、安全（告警、检测规则配置）、管理（仿真控制、系统设置）
  • 告警菜单项加未处理数量的红色角标
  • 仿真运行状态指示灯（绿色脉冲/红色停止）在菜单底部常驻
  • 配色方案优化——当前纯暗色，可加入 ADS-B 航空主题元素（雷达扫描效果、高度表风格）

5.4 仿真控制过于简单

现状：仿真只有一个「启动/停止」按钮和一个飞机数量滑块。启动后飞机在随机位置以随机航向飞行，无法干预。

建议方案：
  • 航线模式：定义几条典型航线（如北京→上海、广州→成都），飞机沿航线飞行而非纯随机漂移
  • 速度控制：仿真倍速滑块（1x 实时 / 10x 快进 / 100x 压力测试）
  • 密度控制：按空域密度分级（稀疏 5 架 / 正常 15 架 / 繁忙 50 架）
  • 攻击计划：编排攻击序列（每 30 秒随机攻击一架、集中攻击某一 ICAO 等），而非手动逐次点击
