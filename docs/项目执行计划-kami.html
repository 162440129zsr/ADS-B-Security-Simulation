01 · Executive Summary

执行摘要

本项目处于整体计划的第二阶段：核心功能开发（2026.07—2026.09）。 当前已完成技术储备、环境搭建与前端详细设计，接下来一个月需要在 后端服务、前端可视化、报文模拟与安全检测四条线上并行推进， 目标是在 8 月 21 日前交付第一版可演示的系统原型。

一个月总目标

打出第一版可演示的系统原型：后端能跑起来 → 数据能模拟生成 → 前端能看到飞机 → 地图上能动 → 异常能告警。核心思路是先跑通链路，再打磨细节。

核心技术栈确认

层级 技术选型 理由
报文模拟 GNU Radio Companion / Java 软件模拟 先纯软件模拟生成，不依赖硬件设备，后续可对接 GNU Radio
后端服务 Spring Boot 3.x + Spring Data JPA 成熟稳定，团队有基础。JPA 快速建模迭代
前端可视化 Vue 3 + Element Plus + ECharts + Leaflet 组件化开发效率高，Element Plus 提供完整 UI 组件库
数据存储 MySQL 8.0 关系型数据库，适合结构化 ADS-B 报文数据的查询与统计
安全核心 区块链溯源 + 身份基广播加密 课题组已有算法基础，先做 AES/HMAC 简化版保证链路通畅
关键判断：从「设计阶段」转入「开发阶段」的最大风险不是技术难度，而是「启动惯性」——文档写得越详细，越容易产生「已经做完了」的错觉。当前最紧迫的事是立即动手写代码，哪怕第一版很粗糙。

风险识别与应对策略

风险 概率 影响 应对策略
加密算法太复杂，一个月集成不完 中 高 先用 AES/HMAC 做简化版，保证链路能跑通。真实算法后续替换，接口不变。
GNU Radio 对接困难，报文模拟卡住 中 中 先用纯 Java 软件模拟生成（随机 + pyModeS 逻辑），不依赖硬件和 GNU Radio。
前端地图性能问题，飞机太多卡顿 低 低 控制模拟飞机 ≤50 架。使用 Leaflet 聚合 Marker。必要时降级为 3 秒轮询。
队友进度不同步，API 接口对不上 中 中 每天 15 分钟同步站会。前后端接口文档先定义再开发。每周检查节点强制对齐。
调试花太多时间，挤占开发时间 中 中 先写单元测试再集成。前 3 天的基础打好（数据库、脚手架、API 框架），后续效率翻倍。
降级原则：遇到阻塞超过半天的技术问题，立即启动降级方案（简化实现），保证每周检查节点的交付物不延期。功能完善可以后续迭代，链路中断不可接受。
