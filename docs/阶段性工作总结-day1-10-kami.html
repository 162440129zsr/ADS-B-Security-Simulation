二、仿真引擎 —— 数据是如何生成的

2.1 飞机种子数据 SimulationService.seedAircraft()

字段生成方式示例值
ICAO 随机 6 位十六进制 A0E1FB、456D92
呼号 航司前缀 (CCA/CES/CSN 等) + 随机 3-4 位数字 CCA1823、CAL9016
纬度 中国空域: 北纬 20°–45° 均匀随机 32.0472（武汉附近）
经度 中国空域: 东经 75°–130° 均匀随机 118.7837（南京附近）
高度 5000–40000 ft 均匀随机 28700 ft（FL287）
速度 200–550 kt 均匀随机 435 kt（约 805 km/h）
航向 0°–360° 均匀随机 142.3°（东南方向）

2.2 飞行位移计算 (Haversine 公式)

每 tick 模拟 30 秒实际飞行（而非 1 秒），确保地图上飞机有肉眼可见的位移。 

speedMs = speedKt × 0.514444       (节 → 米/秒)
dist    = speedMs × 30             (30秒飞行距离)
dLat    = dist × cos(headingRad) / EARTH_RADIUS
dLon    = dist × sin(headingRad) / (EARTH_RADIUS × cos(latRad))
newLat  = lat + toDegrees(dLat)    (边界: 20°–45°)
newLon  = lon + toDegrees(dLon)    (边界: 75°–130°)

计算示例：一架位于 (32.0000, 118.0000) 的飞机，航向 90°、速度 450kt， 每 tick 位移 ≈ 30 × 231.5 m/s = 6.94 km ≈ 0.063°（经度方向）。

2.3 ADS-B 报文生成 generatePositionHex()

按 DO-260B 标准组装 112-bit DF17 报文，格式为： 

| DF(5) | CA(3) | ICAO(24) | ME(56)                      | PI(24)  |
| 10001 | 000   | A0E1FB   | TC(5)+SS(2)+SAF(1)+ALT(12) | CRC占位 |
|       |       |          | +T(1)+F(1)+CPR-LAT(17)      | 000000  |
|       |       |          | +CPR-LON(17)                |         |
 ───────┬────── ──────┬────── ────────────┬────────────── ───┬────
   1 byte  (0x8D)      3 bytes            7 bytes         3 bytes

当前报文生成采用简化 CRC（PI 字段固定 000000），后续可接入真实 CRC-24 校验。高度采用 Q=1 编码（25ft 增量），CPR 采用简化的经纬度小数部分映射。

三、ADS-B 协议解码 —— 报文是怎么解析的

3.1 解码流水线

步骤服务处理内容
1 CrcService 多项式 0xFFFA0480 模二除法，计算 24-bit CRC 余数。余数为 0 = 校验通过
2 AdsbDecoderService 提取 DF（bits 1-5）、ICAO（bits 9-32）、TC（bits 33-37），按 TC 范围分发
3 分发处理 TC 1-4 → 飞机识别（charset map 解码呼号）；TC 9-18 → 空中位置；TC 19 → 速度；TC 31 → 版本
4 CprDecoderService 奇帧+偶帧配对 → 全局解码经纬度；单帧可用参考位置做本地解码

3.2 支持的消息类型

TC 范围类型解码字段
1–4飞机识别呼号（8 个 6-bit 字符 charset 解码）、飞机类别
5–8地面位置CPR 编码经纬度（表面坐标）
9–18空中位置（气压高度）Q-bit 高度解码（25ft 增量）、CPR 编码经纬度
19空中速度Subtype 1/2：E/W + N/S 向量合成地速+航迹角、垂直速率
20–22空中位置（GNSS 高度）GNSS 高度 + CPR 经纬度
31运行状态ADS-B 版本号（v0/v1/v2）

3.3 CPR 位置解码机制

Compact Position Reporting (CPR) 是 ADS-B 的核心编码方案——将 17-bit 经纬度打包在报文中，用奇偶帧的时间差序列来恢复全局位置： 

┌─ 偶帧 ─┐   ┌─ 奇帧 ─┐
Lat: 17 bits   Lat: 17 bits    →  j = floor(59×Even/2¹⁷ − 60×Odd/2¹⁷ + 0.5)
Lon: 17 bits   Lon: 17 bits    →  dLon = 360/NL(纬度), 全局解算

实现细节：ConcurrentHashMap<String, CprFrame> 缓存每架飞机的奇偶帧， computeNL(lat) 计算纬度带数量，mod(a,b) 处理取模运算， normalizeLat/Lon 处理经纬度归一化。

四、安全检测模块 —— 5 条检测规则

#检测项等级触发条件检测逻辑
1 CRC 校验失败 红色 CRC 余数 ≠ 0 报文在传输过程中被篡改，CRC 完整性校验不通过
2 位置异常跳变 红色 30 秒内位移 > 100 km Haversine 公式计算前后两条报文间距离，超过阈值判定为 GPS 欺骗
3 高度异常变化 橙色 30 秒内高度变化 > 5000 ft 同一飞机相邻报文高度差超过阈值，判定为高度篡改
4 速度超限 橙色 速度 > 650 kt 超过民航飞机最大巡航速度，判定为数据异常
5 疑似重放攻击 红色 60 秒内相同 hex 报文重复出现 缓存近期报文 hash，相同 ICAO + 相同 hex 在窗口内重复 = 重放
去重机制：同一飞机的同类型告警仅保留一条未处理记录（ConcurrentHashMap.newKeySet() 追踪 icao:type 键）。 标记"已处理"后自动清除去重缓存，允许同类告警再次触发。避免每秒重复刷屏。

五、攻击模拟系统

攻击类型API 参数攻击效果
📍 位置欺骗 position 随机选一架飞机，经纬度各偏移 ±2.5°（约 250–500 km），模拟 GPS 欺骗
📏 高度篡改 altitude 高度瞬间变化 ±8000 ft，模拟高度数据被恶意修改
⚡ 速度超限 speed 速度设为 700–800 kt，触发速度超限告警
🔐 CRC 篡改 crc 修改报文 PI 字段使 CRC 校验失败（crcValid = false）
🔄 重放攻击 replay 重复发送该飞机上一条相同 hex 报文，触发重放检测
🎲 随机攻击 不传参 从前 4 种类型中随机选一种，增加不可预测性

攻击模拟 API：POST /api/simulation/attack {"attackType": "position"}。 前端仿真控制页提供 6 个按钮，点击攻击后 → 后端注入异常 → 安全检测模块自动触发告警 → 告警页面实时可查。

九、后续待改进项

#改进项优先级具体内容
1 真实 CRC-24 生成 高 当前 generatePositionHex() 中 PI 字段固定 000000，需接入 CrcService 生成真实校验码。修改后攻击模拟的 CRC 篡改才能正确被检测
2 MySQL 持久化 高 当前默认 H2 内存库，重启数据丢失。切换至 MySQL 后，告警记录和历史报文可持久保存，适合演示和汇报
3 位置跳变检测完善 高 当前仅对比相邻两条报文，正常 tick 间隔 1 秒。攻击注入后需配合攻击前后位置对比。可改用"滑动窗口+中位数"检测
4 告警页面增强 中 前端 SecurityAlertView 增加统计卡片（红/橙/黄计数）、一键标记已处理、关联飞机详情跳转
5 数据可视化增强 中 DataView 增加高度变化折线图、速度分布图、报文类型统计柱状图；选中一架飞机查看其实时航迹
6 首页仪表盘完善 中 地图右侧面板增加安全态势摘要（最近 N 条告警）、底部实时报文滚动日志
7 真实 CRC 在仿真中的校验 中 tick 生成报文后调用 CrcService.isValid() 做真实校验（当前 crcValid 直接设 true）
8 多飞机轨迹显示 低 地图上同时显示多架飞机历史轨迹（不同颜色区分），增强演示效果
9 WebSocket 实时推送 低 当前 3 秒轮询，改为 WebSocket 推送可降低延迟，飞机位置更实时
10 加密模块集成 低 按项目整体计划，第三周集成区块链+身份基广播加密（EncryptionService）
11 数据导出功能 低 CSV 导出报文记录和告警记录，用于项目文档和报告
12 单元测试补充 低 为 SecurityCheckService 和 SimulationService 补充 JUnit 测试用例
