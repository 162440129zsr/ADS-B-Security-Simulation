一、现网生态总览

核心发现：现有 ADS-B 开源生态由五层独立工具构成——信号生成、报文解码、可视化展示、安全检测、仿真模拟。每层都有成熟项目，但没有任何一个项目把五层整合在一起。你的项目恰好填补了这个空白。

二、重点开源项目详解

🏆 tangram — 最值得参考架构

open-aviation/tangram · Python + Rust + Vue + Redis · JOSS 学术期刊发表 · 荷兰 NWO 基金资助
核心理念插件化、完全解耦的模块化 ATM 研究平台。所有组件通过 Redis pub/sub 通信，可动态加载/卸载插件。
技术亮点① Rust 写的 jet1090 解码器（性能远超 dump1090）；② Vue + Deck.gl 前端动态加载插件 UI；③ Redis 消息总线解耦所有组件；④ Apache Arrow RecordBatch 高性能数据存储
可借鉴之处插件架构设计、Rust 解码器集成、前端 Deck.gl 航空可视化、WebSocket + Redis 实时数据流
GitHubgithub.com/open-aviation/tangram

🔐 DApIA-Project — 安全检测功能最接近你的需求

DApIA-Project · Python · 法国学术项目
ADSB-VisualizerWeb 端 ADS-B 数据可视化回放器。支持播放/暂停/快进/跳转、多机跟踪、航迹显示、高度/速度曲线图。在线 Demo: adsb-visualizer.web.app
Anomaly-DetectionPython 异常检测库（pip install AdsbAnomalyDetector）。一个 predict() 函数，输入最近 1 秒的报文列表，返回 spoofing/flooding/replay 三种异常标记。内部维护历史报文缓冲区。
可借鉴之处攻击回放可视化设计、predict() 统一检测接口、detection + visualizer 联动
GitHubgithub.com/DApIA-Project

📡 pyModeS — 你的解码器的 Python 原型

junzis/pyModeS · Python · TU Delft 航空航天工程学院 · ~800 stars
解码能力DF17/18 ADS-B 全部报文类型（识别、位置、速度）、DF20/21 Mode-S Comm-B、气象报告。CPR 全局/参考位置解码。高度 Q-bit/Gillham 双模式。速度矢量解码。
附带工具modeslive 实时流量查看工具；内置 simulator.py 模块（功能未文档化）；TCP 客户端流式解码；Extra 模块：气象报告、EHS 数据
可借鉴之处这是你的 AdsbDecoderService + CprDecoderService + CrcService 的原型。你的 Java 代码本质上是 pyModeS 的移植版。建议对比验证解码准确性。
GitHubgithub.com/junzis/pyModeS

🖥 Virtual Radar Server — 唯一支持模拟器同步的

virtualradarserver.co.uk · .NET/C# · Windows/Linux(Mono)
独特功能可与 Microsoft Flight Simulator 2020 / XPlane 同步，将模拟飞行中的飞机显示在 ADS-B 雷达界面上。无需任何 SDR 硬件即可看到"假飞机"在地图上飞行。
可借鉴之处模拟器数据对接方案、Google Maps 插件架构、Web 端雷达界面设计
网站virtualradarserver.co.uk

🛩 skies-adsb — 视觉效果最炫

machineinteractive/skies-adsb · JavaScript/WebGL · ~500 stars
核心功能纯浏览器端 3D 空中交通显示。Three.js 渲染飞机模型 + 地形 + 空域。支持自定义 3D 地图图层。PWA 离线可用。连接本地 dump1090 数据源。
可借鉴之处3D 飞机可视化（答辩时比 2D 地图震撼得多）、WebGL 渲染性能优化
GitHubgithub.com/machineinteractive/skies-adsb

3.2 差异化定位

你的系统是唯一一个覆盖 "生成报文 → 解码 → 仿真飞行 → 攻击注入 → 安全检测 → 告警管理 → 地图可视化" 完整链路、并提供 Web 管理界面的系统。

现有系统的组合模式：dump1090(解码) + tar1090(展示) = 只能看真实飞机；pyModeS(解码) + 自写脚本 = 学术研究；GNU Radio(信号) + HackRF(发射) = 攻击实验。每套工具链都需要用户自己拼装。

你的系统提供了一站式体验：启动一个 jar 包 → 浏览器打开 → 看到飞机在飞 → 点一下攻击按钮 → 看到告警触发 → 看到轨迹变色。这种开箱即用的完整体验是其他所有项目都不具备的。

5.2 dump1090 的数据输出格式（生态标准）

dump1090 的 TCP 30003 端口输出的 SBS-1 格式是 ADS-B 生态的事实数据交换标准。如果你的系统能对接 dump1090 的数据格式，就能从"纯仿真"升级为"仿真 + 真实数据混合"。只需实现一个 TCP 客户端读取 dump1090 的数据流即可。

5.3 pyModeS 的解码接口设计

# pyModeS 的函数式 API 风格
pms.adsb.icao(msg)           # → "6F922D"
pms.adsb.callsign(msg)       # → "CCA3124"
pms.adsb.altitude(msg)       # → 30000
pms.adsb.velocity(msg)       # → (450, 270, 0, 'GS')
pms.adsb.position(msg_even, msg_odd, t_even, t_odd)  # → (32.45, 118.12)

你的 AdsbDecoderService 可以封装类似的简洁 API，方便后续扩展其他报文类型。

六、结论与建议

6.1 你的项目定位

一句话：面向 ADS-B 安全的一站式软件仿真验证平台——覆盖报文生成、解码、飞行器仿真、攻击注入、安全检测、告警管理、地图可视化的完整链路。
一句话差异：现有工具全是"单层零件"，你的系统是"整车"。

6.2 答辩时可引用的话术

  • "现有 ADS-B 开源生态由 30+ 个独立工具构成，但没有任何一个系统将仿真、攻击、检测、可视化整合在一起。我们的工作填补了这个空白。"
  • "dump1090 能解码、tar1090 能展示，但它们都只能处理真实飞机的数据，不支持安全攻防实验。DApIA 能做异常检测，但没有仿真引擎和前后端系统。tangram 架构最先进，但不涉及安全。"
  • "我们的报文编解码参考了 TU Delft 的 pyModeS 库（学术界 ADS-B 解码的事实标准），CRC-24 实现严格遵循 DO-260B 标准。"
  • "与硬件方案（SDR+GNU Radio）相比，纯软件方案的独特性在于：可在任何环境部署、可批量复现测试、可量化为安全指标（检出率/误报率）。"
